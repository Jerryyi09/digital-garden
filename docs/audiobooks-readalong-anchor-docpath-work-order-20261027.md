## 1. 兜底句引用的段落锚点被切句步骤删除（P1，治本，退役补丁）
- **断层**：`SENTENCE_FROM_PARAGRAPH` 兜底句的语义是"高亮整个段落"，它引用段落锚点（无 id 块元素由 `prepare_paragraphs` 分配的 `fast-*` id）；可 `mark_sentences` 及之后的清理环节，把已被句子 span 取代的外层块 id 剥离了。锚点的生产方和使用方对"这个 id 是否还在"不一致。
- **修法**：
  1. 切句和清理时，**保留所有被 timeline 引用的块级 id**（至少是兜底句引用的那些）。兜底句高亮整段，正是设计语义；
  2. 把不变量"timeline 中每一个 `fragment`/`sourceSentenceFragment` 都存在于最终正文 DOM 中"作为**生成时就保证**的约束：在写出 timeline 之前统一断言，违反即视为脚本错误，并写明是哪一段；
  3. **退役** `pipeline.py` 约 1240–1281 行按文本唯一匹配的重绑逻辑（包括昨天为《千面英雄》加的重绑），连同它专属的测试一起删除，并说明测试数的变化。
- **不要**改为"回退到段落首句"：那样会让整段的时长只高亮第一句，孩子看到的高亮是错的。**不要**新增 `timingStatus`。
- 测试：用合成 EPUB 覆盖三种无 id 块元素（带 smallCaps 混排的 `<p>`、短题献 `<p>`、`<h2>` 章节标题），兜底句的锚点必须存在于最终 DOM，审核不报 `DOM_REFERENCE_BROKEN`。

## 2. timeline 的 `document` 必须是真实文件名（P2）
- **裁决**：第一层检查里的 `%` 检测和"不解码直接拼接路径"**不是误报，保留**。timeline 的 `document` 是交给前端的输出，前端会原样拿去请求 Alist；带 `%20` 就取不到正文（10-25《1984》事故，手册踩雷表有记录）。EPUB 内部 OPF 的 `href` 写成 `%20` 是合法的，但那是输入，不是输出。
- **修法**：映射生成 timeline 时，把 `document` 统一解码成 EPUB 解包后的真实相对路径（以 ZIP 条目名为准）。同一处统一处理，不要在多个读盘点各自 `unquote`。
- 第一层检查：去掉 `break`，改为收集全部问题后一起报告；`%` 检测保留。
- **不要换《1984》的 EPUB**，修好后现有这本就能通过。
- 测试：OPF 里混用空格和 `%20` 两种 `href` 写法时，timeline 的 `document` 全部是真实文件名，第一层检查通过。
