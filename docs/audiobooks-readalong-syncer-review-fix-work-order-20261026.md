## 1. 书名首尾空格导致 NUC 重复目录；远端建目录经过 shell
- 现状：`sync_book_to_nuc` 直接用本地目录名（只做了 NFC 规范化）拼出远端路径。本地《悉达多 Siddhartha␠》（末尾有空格）一同步，就会在 NUC 上新建一个末尾带空格的目录，与已有的规范目录并存，这与 10-26 刚清理掉的重复目录属于同一类问题。另外，远端用 `ssh … "mkdir -p \"…\""` 建目录，要经过远端 shell 解释，书名里含 `"`、`$`、反引号时会出错，甚至被当作命令执行。
- 修法：
  1. 远端书目录名**以 NUC 上已存在的规范目录为准**：同步前在同一次 SSH 调用中列出分类目录，按"NFC 规范化 + 去掉首尾空格 + 私有区字符还原为空格"后的名字匹配。匹配到就用 NUC 上的真实名字；匹配不到、确实是新书时，用规范化后的名字新建。一律不新建名字只差首尾空格的目录。
  2. 不再通过远端 shell 建目录：改用 rsync 的 `-R`，以 `<分类目录>/./<书名>/…` 作为源，让 rsync 自己创建目录；或者使用 `--mkpath`（先确认 NUC 上的 rsync 版本支持）。
  3. 本地有首尾空格的目录名（目前已知《悉达多 Siddhartha␠》）列出清单，**经用户确认后**再改名；改名后，本地发布记录和缓存都不受影响（缓存以音频指纹为键）。
- 测试：书名末尾带空格、名字里带 `"` 和 `$`、NUC 上已存在私有区字符目录名，三种情况都只能同步到规范目录，不得产生新目录。

## 2. 每次同步都列入全部音频和 EPUB
- 现状：`build_book_sync_manifest` 把 manifest 里的全部音频和书目录里的全部 EPUB 都列入同步。只要 NUC 上已有的文件和本地的修改时间不一致（例如用户手动拷贝过），rsync 就会把好几个 GB 的音频整个重传，并用 `--backup` 把旧文件备份到 `/home/hp/readalong-sync-backup/`，可能写满系统盘（总共 218G，目前可用 135G）。重新发布一本已上线的书，实际只需要同步 `readalong/`、当前版本目录、封面和简介。
- 修法：分两组同步。
  - **跟读组**：`readalong/`、当前版本目录、`cover.jpg`、`summary.txt`。照常比较并覆盖，覆盖时备份。
  - **源文件组**：音频和 EPUB。使用 `--ignore-existing`，只补 NUC 上缺失的文件，**绝不覆盖、绝不备份已有的音频**。确实需要替换音频的情况，由用户明确指示，单独执行。
- 测试：生成的命令里，源文件组必须带 `--ignore-existing`；NUC 上已有同名音频、但修改时间不同时，不得发生传输。
- 汇报：给出对一本已上线书重发时，修改前后的实际传输字节数。
